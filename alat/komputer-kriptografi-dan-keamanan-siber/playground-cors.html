Aturan yang sebenarnya dipakai browser

Same-origin selalu bebas — kalau protokol, domain, dan port persis sama, tidak ada pengecekan CORS sama sekali. Begitu salah satu beda (termasuk cuma beda subdomain atau port), itu sudah dianggap origin lain.

Untuk request sederhana (GET/POST dengan header standar), browser tetap mengirim request-nya dan menerima responsnya — yang diblokir adalah izin JavaScript untuk membaca hasilnya, kalau header Access-Control-Allow-Origin tidak cocok. Untuk request kompleks (method seperti PUT/DELETE, atau header custom), browser mengirim preflight — request OPTIONS terpisah bertanya izin dulu — dan kalau preflight-nya saja sudah ditolak, request asli tidak pernah dikirim sama sekali.

Kasus yang sering bikin bingung: Access-Control-Allow-Origin: * terlihat "paling terbuka", tapi begitu request menyertakan cookie/kredensial, wildcard ini tidak sah dipakai browser — server wajib menyebut origin spesifik plus header Access-Control-Allow-Credentials: true. Ini bukan bug, ini disengaja: mencegah situs mana pun diam-diam memakai cookie sesi Anda di situs lain.

Bagian dari Laboratorium JAZMI — ini simulasi murni (tidak ada request jaringan sungguhan dikirim); logikanya meniru aturan CORS asli browser untuk keperluan belajar.
